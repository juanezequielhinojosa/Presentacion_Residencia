Diapositiva 02 / 06 Fundamentos Web

Modelo Cliente-Servidor

Concepto central: ¿Por qué separamos la interfaz del almacenamiento?

  • 📱
    El Cliente (Solicitante)

    Es la aplicación o navegador que usa el usuario (Chrome, Safari, celular). Se encarga de mostrar la interfaz gráfica y pedir datos.

  • 🖥️
    El Servidor (Proveedor)

    Una computadora en la nube conectada 24/7 con alta disponibilidad. Recibe peticiones, procesa lógica, valida reglas y devuelve respuestas.

🍽️
El Cliente

El comensal sentado en la mesa consultando la carta y haciendo pedidos.

👨‍🍳
El Servidor

La cocina que prepara, custodia las recetas y despacha los platos solicitados.

❓ Pregunta disparadora para el curso Ver respuesta
¿Por qué no guardamos la lista de productos dentro de la misma página web del teléfono del usuario?

Porque si modificamos el precio de un dragón articulado o nos quedamos sin filamento PETG, tendríamos que actualizar la aplicación en los teléfonos de miles de usuarios. En el servidor, se cambia una sola vez y todos lo ven al instante.

🎙️ Palabras del Docente / Analogía

"Es como un restaurante: ustedes son el Cliente sentados en la mesa consultando la carta; la Cocina es el Servidor que prepara y entrega la información solicitada."

Diapositiva 03 / 06 Estructura de Datos

Base de Datos Relacional

Concepto central: El lugar ordenado y tipado donde guardamos la información.

  • 📊
    Tablas, Filas y Columnas

    Columnas: Atributos del producto (nombre, precio, material).
    Filas (Registros): Cada pieza 3D individual guardada en el taller.

  • 🔒
    Tipos de Datos y Clave Única (ID)

    Texto (nombre), Números decimales (precio), Enteros (stock) y un id irrepetible (Primary Key) para no confundir piezas.

❓ Pregunta disparadora para el curso Ver respuesta
Si un precio cambia, ¿dónde nos conviene modificarlo: en 10 páginas HTML distintas o en una sola tabla centralizada?

¡En una sola tabla centralizada! Toda la web se alimenta automáticamente de esa única fuente de verdad (Single Source of Truth).

Diapositiva 04 / 06 El Puente de Conexión

API REST: El Mensajero

Concepto central: El puente de comunicación entre el Cliente y la Base de Datos.

  • 🔌
    API (Interfaz de Programación de Aplicaciones)

    Conjunto de reglas y formatos para que dos sistemas independientes (nuestro JavaScript y Supabase) se entiendan sin saber cómo está programado el otro.

  • 📬
    Métodos HTTP Básicos

    GET para pedir y leer productos, POST para crear uno nuevo, PUT/PATCH para modificar precio, DELETE para borrar.

  • 🔑
    Credenciales de Conexión

    URL del Proyecto: La dirección de la casa.
    Anon Public Key: La llave autorizada para leer la vidriera.

🤵 El Mozo del Restaurante

"Toma el pedido de la mesa (GET /productos), va a la cocina, trae los datos estructurados en formato JSON y los sirve en la pantalla."

// Cómo pedimos los datos con JavaScript:
const { data } = await supabase
  .from('productos')
  .select('*');
🎙️ Palabras del Docente / Analogía

"La API es el mozo del restaurante: toma el pedido del cliente ('Tráeme la lista de productos'), va a la cocina (servidor), busca los datos en la heladera (base de datos) y se los sirve a la mesa en formato digital."

Diapositiva 05 / 06 Nuestra Plataforma Cloud

¿Por qué Supabase?

Concepto central: Nuestra plataforma Backend-as-a-Service (BaaS) moderna y open-source.

  • 🐘
    Motor PostgreSQL en la Nube

    La base de datos relacional más robusta y respetada del mundo, sin necesidad de instalar programas pesados en las computadoras del colegio.

  • ⚡
    Generación Automática de APIs REST

    Apenas creas una tabla en Supabase, la API REST ya está creada y funcionando automáticamente sin escribir código de backend.

  • 🖥️
    Table Editor Visual e Intuitivo

    Panel web muy parecido a una hoja de cálculo para cargar fotos, editar precios y filtrar productos con unos pocos clics.

🚀 Desarrollo Ágil Maker

En vez de pasar 3 semanas configurando Linux, servidores Apache o puertos, con Supabase tenemos el backend listo en 5 minutos para enfocarnos en fabricar piezas 3D.

🛡️ Políticas de Seguridad (RLS)

Permite que cualquier cliente lea los productos de la vidriera, pero solo nosotros con clave de taller podamos modificarlos o eliminarlos.

🎙️ Palabras del Docente

"Supabase nos da el servidor, la base de datos relacional y la API REST ya listas en cuestión de minutos, permitiéndonos enfocar en nuestro catálogo 3D sin configurar servidores físicos."

Diapositiva 06 / 06 Práctica Guiada en Vivo

¡Manos a la Obra! (TP N.° 1)

Consigna paso a paso: Creación del backend y tabla de productos para Universo 3D.

  • 1
    Registro y Creación de Proyecto Crear cuenta en supabase.com e iniciar el proyecto con nombre Universo-3D.
  • 2
    Crear la Tabla 'productos' Definir campos: id, nombre, descripcion, precio, image_url, material y stock.
  • 3
    Carga Inicial de 3 Ítems del Taller Ingresar al menos 3 piezas 3D reales con fotos y precios representativos.
  • 4
    Extraer Credenciales API Copiar en el archivo el SUPABASE_URL y SUPABASE_ANON_KEY desde Project Settings -> API.
  • 5
    Comprobación en el SQL Editor Ejecutar la consulta SELECT * FROM productos; y verificar los resultados devueltos.
Script SQL rápido para la clase Opcional para SQL Editor
CREATE TABLE productos (
  id BIGSERIAL PRIMARY KEY,
  nombre TEXT NOT NULL,
  descripcion TEXT,
  precio NUMERIC(10,2) NOT NULL,
  image_url TEXT,
  material TEXT DEFAULT 'PLA+',
  stock INT DEFAULT 10
);

-- Habilitar lectura pública (RLS)
ALTER TABLE productos ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Lectura pública" ON productos FOR SELECT USING (true);
